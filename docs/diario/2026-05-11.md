## O que foi feito

### Bugs de produção corrigidos (continuação da sessão anterior)
- **422 em `/api/tasks/pending-review`**: rota estava definida depois de `/{task_id}` no FastAPI. Movida para antes da rota parametrizada.
- **Tela em branco no Cloudflare**: `.env.production` estava no `.gitignore`, então o build não tinha as variáveis `VITE_SUPABASE_URL` e `VITE_ANON_KEY`. Adicionada exceção no `.gitignore` e arquivo commitado (valores são públicos — `sb_publishable_`).
- **SPA routing no Cloudflare Pages**: sem o arquivo `public/_redirects`, acessos diretos a rotas como `/configuracoes/google/callback` retornavam 404. Arquivo `/* /index.html 200` criado.
- **503 em `/api/settings/google/auth-url`**: variáveis do Google (`GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_OAUTH_ENCRYPTION_KEY`, `FRONTEND_URL`) não estavam no Render. Usuário adicionou via dashboard.

### Bug no Calendar sync corrigido
- **400 `syncTokenWithNonDefaultOrdering`**: o parâmetro `orderBy` estava sendo enviado junto com `syncToken`, o que a API do Google não permite. Corrigido: `orderBy` só é enviado no primeiro polling (sem token).

### Fluxo de revisão redesenhado
Após entrevista com o usuário, redefinido o comportamento de confirmação de tarefas vindas do Calendar/Tasks:
- **"Confirmar"** agora confirma imediatamente no backend e abre o modal de edição em seguida para o usuário complementar dados (executor, score, prazo)
- **`list_today`** passou a excluir tarefas `is_pending_review = True` para não aparecerem em duplicata no Kanban
- **`list_today`** teve o filtro `scheduled_window_start <= now` removido — todas as tarefas ativas aparecem no Kanban, o agrupamento por data já cuida das futuras

### Sincronização bidirecional com Google Tasks implementada
- `poll_tasks()` adicionado ao ciclo de sync: lê a lista "AgroecologIA" no Google Tasks e importa como `pending_review` tarefas que não têm `google_task_id` correspondente no app
- App é fonte da verdade — edições feitas no Google Tasks em tarefas existentes não sobrescrevem o app
- `complete_task()` corrigido: agora tenta a lista primária e faz fallback para a lista secundária em caso de 404 (corrige conclusões silenciosas que usavam a lista errada)
- Parsing de data do Google Tasks corrigido: `datetime.strptime(due_str[:10], "%Y-%m-%d")` substituiu `fromisoformat()` que falhava silenciosamente com o formato de milissegundos da API

### Decisão de produto consolidada
- Data do Google Calendar/Tasks é metadado de origem (`scheduled_window_start`), não vira prazo (`scheduled_window_end`) automaticamente
- O modal de confirmação não pré-preenche o campo de prazo com a data do Google — usuário define quando quer que a tarefa seja feita

## Decisões tomadas

| Decisão | Motivação |
|---|---|
| App é fonte da verdade para edições | Evitar conflitos: Google Tasks edita só título/data, app tem executor/score/dependências |
| Tarefas do Google entram como pending_review | Usuário precisa definir executor e confirmar antes de entrar no Kanban |
| `list_today` retorna todas as tarefas ativas | Kanban é o painel completo, não só "hoje" — grouping por data trata o que é futuro |
| "Confirmar" confirma + abre modal | Usuário quer tarefa imediatamente na lista mas complementa dados logo em seguida |
