### 1. Responsáveis, Tipos de atividade e Culturas — dinâmicos

Problema: executors hardcoded como enum Python; tipos e culturas hardcoded em `activityTags.ts`.

Solução completa:

**Backend:**
- `Executor` enum removido de `models/task.py` — `executor` virou `str` (slug-based, backward compatible)
- Novo `models/config.py`: modelos `Person`, `ActivityType`, `Culture` (tabelas novas, criadas automaticamente por `init_db()`)
- `services/config.py`: `PeopleService`, `ActivityTypeService`, `CultureService` com CRUD completo
  - Deletar pessoa → redefine `executor = "nao_atribuido"` em todas as tarefas afetadas
  - Deletar tag → remove o trecho `[NomeDaTag]` dos títulos das tarefas (lógica `_strip_tag_from_title`)
  - `seed_config()`: popula as tabelas se estiverem vazias (4 pessoas, 13 tipos, 5 culturas — espelha dados anteriores)
- `api/routes/config.py`: endpoints REST `/api/config/people`, `/api/config/activity-types`, `/api/config/cultures`
- `main.py`: registra router de config + chama `seed_config()` no lifespan

**Frontend:**
- `api/config.ts`: cliente para os endpoints de configuração
- `hooks/useConfig.ts`: hooks `usePeople`, `useActivityTypes`, `useCultures`, `usePersonName`
- `constants/activityTags.ts`: reescrito — funções de parsing/building agora aceitam listas dinâmicas; fallbacks estáticos preservados para compatibilidade
- `TaskCard.tsx`: usa `usePeople` + `useActivityTypes` para nomes dinâmicos e lista de executors no hover
- `CreateTaskModal.tsx`: usa hooks dinâmicos para tipo, cultura e responsáveis — EXECUTORS hardcoded removido

  - Todas as pessoas com login mostram badge "login"
